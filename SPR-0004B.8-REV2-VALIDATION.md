# SPR-0004B.8-REV2 Validation

## Build matrix

Run all four normal firmware builds:

```bash
cd firmware/esp32-wroom
pio run -e esp32dev
pio run -e esp32dev-aws

cd ../lilygo-t-a7670
pio run -e lilygo-t-a7670
pio run -e T-A7670X-AWS
```

## ESP32-WROOM regression

1. Boot an already configured device.
2. Confirm the existing Preferences configuration is retained.
3. Open the normal configuration page and save without changing values.
4. Confirm reboot and normal telemetry operation.
5. Call `GET /api/config` and verify valid schema-version-1 JSON.
6. Export through the existing download route.
7. Import the exported JSON through the existing WebUI route.
8. Call `GET /api/readiness`.
9. Complete and restart onboarding once.
10. Perform factory reset and confirm return to AP onboarding.

## LilyGO regression

Repeat the equivalent sequence using Wi-Fi or LTE:

1. Existing configuration survives firmware update.
2. Configuration save and reboot work.
3. Config export/import work.
4. `/api/readiness` returns valid JSON.
5. Onboarding complete/restart works.
6. Factory reset returns to onboarding.
7. MQTT/AWS variant reconnects using the retained configuration.

## Import checks

- Import a legacy backup without `schemaVersion`: accepted.
- Import a schema-version-1 backup: accepted.
- Import JSON with `schemaVersion: 2`: rejected.
- Import malformed JSON: rejected.
- Import a partial document containing only `vehicleId`: other fields remain unchanged.
- Import without secret fields: stored secrets remain unchanged.

## Expected result

No user-visible behaviour differs from REV1. The change is successful when all configuration entry points use the board manager and both boards retain their existing configuration and service behaviour.
