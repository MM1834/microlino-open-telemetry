# SPR-0004B.6 Architecture

## Purpose

SPR-0004B.6 establishes the firmware foundation for guided device onboarding without introducing a second configuration system.

## Layers

- `firmware/common/onboarding/onboarding.h`: platform-neutral onboarding vocabulary, step IDs and board capabilities.
- Board configuration (`AppConfig` / `LilygoConfig`): persists only completion state alongside existing settings.
- Existing WebUI and configuration handlers: remain the source of truth for network, vehicle, service and CAN settings.
- Existing health/status APIs: remain the basis for later validation steps.

## State model

The first increment exposes seven stable step identifiers:

1. Welcome
2. Hardware
3. Connectivity
4. Vehicle
5. Services
6. Validation
7. Finish

This patch implements the foundation, first-entry page, progress indicator, capability reporting, completion and restart state. Detailed forms continue to use the existing configuration pages.

## Deliberate limits

The patch does not refactor the LilyGO `common_bridge.cpp` compilation strategy. That change is larger and should be handled separately after both board builds are stable.
