# HIS-001 — Bounded Telemetry History Pilot

> **Status:** Backend and hosted portal deployed; observation pending
>
> **Date:** 2026-08-04

## Objective

Add a measurable, low-cost 31-day history pilot for SOC, charging state, plugged
state and speed
without changing current-state semantics, live delivery or vehicle access
isolation.

## Delivery sequence

1. Measure normal publish volume over at least seven days.
2. Deploy the TTL table and API with history disabled.
3. Validate existing snapshot, WebSocket and cross-user denial tests.
4. Enable SOC and charging for one controlled pilot cohort.
5. Confirm the 5-minute bucket ceiling and daily write alarm.
6. Enable speed at one-minute active-driving buckets with a terminal zero marker.
7. Validate 24-hour, 7-day and 30-day API/portal ranges.
8. Observe the first 31-day TTL boundary and record actual AWS costs.

The publish baseline was measured and the infrastructure deployed. SOC, charging
and speed are enabled only for `pioneer`, at 5-minute core and 15-minute
motion cadence. Authenticated History acceptance, live regression and the hosted
portal deployment passed. The first moving-road observation and TTL/cost evidence
remain open.

## Acceptance gates

- feature flag remains off by default;
- an empty vehicle allowlist produces no history writes;
- history failures cannot fail live state or fan-out;
- unauthorized history reads return non-enumerating 404;
- storage is capped at 31 days; core signals are capped at 864 writes/vehicle/day
  and Speed is bounded by active-driving minutes plus journey-end markers;
- core and motion bucket intervals are independently configurable at 1, 5, 15,
  30 or 60 minutes; default-cadence write ceilings remain the pilot baseline;
- daily consumed writes are alarmed and reads/writes are measurable;
- portal uses server history for AWS and local history only for legacy MQTT;
- all local backend authorization and JavaScript syntax tests pass.

After the first road-test evidence, the Speed pilot was refined in the repository:
one sample per active-driving minute, an immediate positive-to-zero journey-end
marker, suppression of repeated standstill zeroes and API-side mean/maximum
aggregation into the existing 5-minute, 30-minute and 2-hour portal resolutions.
Firmware and live-state semantics remain unchanged. The backend refinement was
deployed on 2026-08-04; the hosted static portal was uploaded and accepted on
2026-08-09.

## Validation evidence

On 2026-08-04:

- `python3 -m unittest cloud/aws/foundation/tests/test_onb_authorization.py` — 15 passed;
- `node --check` passed for the provider, app and history chart;
- `git diff --check` passed.

CloudFormation deployment, hosted browser checks, frequency measurement and cost
observation were initially not claimed. Later on 2026-08-04 the AWS session was
renewed and the following deployed evidence was added:

- stack `mot-aws-3-1` reached `UPDATE_COMPLETE` twice: fail-closed infrastructure,
  then `pioneer` core-signal activation;
- 1,761,194 invocations were measured across 119 active hourly datapoints from
  2026-07-28 through 2026-08-04, with regular plateaus near 17,400/hour;
- Health returned 200 and the unauthenticated history endpoint returned 401;
- the disabled deployment had no History `PutItem` IAM permission and zero rows;
- after core activation the table remained empty because `pioneer` was offline;
- Cost Explorer returned `AccessDeniedException`.
- a subsequent no-replacement update enabled Speed for `pioneer` with
  independently configurable 5-minute core and 15-minute motion intervals.
- a later no-replacement update enabled one-minute active-driving Speed for both
  allowlisted identities; both deployed Lambda packages and the 60-second runtime
  parameter were read back, Health passed, History remained protected by 401
  without a token and the daily-write alarm remained `OK` at threshold 2,100.
- the current static portal package was uploaded on 2026-08-09; smartphone and
  desktop acceptance passed, including the five History diagrams and retained
  24-hour/7-day/30-day selection.

The three current vehicle IDs are simulated identities produced by connecting one
available Microlino alternately to different telemetry devices. GPS history was
kept out of HIS-001 because paired location retention and OpenStreetMap route
rendering are a separate privacy and UI scope; live GPS remains supported.

A short live check stored SOC 99 and 100 in consecutive buckets plus Speed 0.
`charging/is_charging` remained false during physical charging and requires
decoder/signal validation. ODO was removed after one sample because total mileage
is monotonically cumulative and adds little pilot value; the row expires by TTL.
Plugged was added as a separate 5-minute boolean series while the existing
`charging/is_charging` name and semantics remain unchanged for decoder evidence.

On 2026-08-11 a follow-up added a bounded range-forecast slice.
Changed odometer values are sampled at the core bucket cadence and combined with
raw SOC and charging history server-side. The API returns a 30-day, maximum
ten-journey forecast basis; the shared portal renders the personal forecast,
distance/journey evidence and the fixed SOC comparison in both responsive
layouts. Local authorization/contract tests and desktop/smartphone visual checks
passed. The controlled `mot-aws-3-1` update then reached `UPDATE_COMPLETE` without
resource replacement. Both Lambdas reported successful updates, Health returned
200, History remained JWT-protected by 401, the 2,100-write alarm remained `OK`
and deployed-template readback contained the ODO and forecast markers. Hosted
`/dashboard/` and `/motbeta/` upload and live journey accumulation remain open.
