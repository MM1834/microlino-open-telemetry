# SPR-0004B.5 — Multi CAN Profile Foundation

> **Status:** Historical sprint record; current implementation is documented elsewhere
>
> **Audience:** Firmware maintainer and auditor

## Goal

Introduce a shared, persistent CAN profile selection for ESP32-WROOM and LilyGO without changing MQTT topics, AWS services, ABRP or the dashboard.

## Delivered

- central profile registry with stable IDs and metadata
- profile-aware decoder engine
- existing Display-CAN decoder retained as the active production profile
- Standard-CAN no-op template without speculative PIDs
- persistent selection in both firmware variants
- profile selection in both local configuration UIs
- active profile and implementation state in diagnostics
- configuration export/import support
- architecture and validation documentation

## Explicitly out of scope

- new CAN IDs or scaling
- AWS changes
- telemetry history
- ABRP/GPS changes
- LTE work
- AWS OTA

## Compatibility

The default remains Display CAN. Existing Standard-CAN configuration value `2` remains valid. Obsolete/unknown values are normalized to Display CAN, preventing accidental use of an undefined decoder.
