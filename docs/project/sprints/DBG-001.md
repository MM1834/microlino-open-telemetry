# DBG-001 — Bounded Vehicle Telemetry Debug Capture

> **Status:** Closed — bounded capture and reusable diagnostic tooling accepted
>
> **Started:** 2026-09-01
>
> **Owner:** Repository maintainers

## Objective

Capture high-cadence scalar Display, charging and BMS telemetry for one explicitly
approved vehicle during a short diagnostic window without changing vehicle or
firmware behaviour and without weakening normal History cost controls.

## Trigger

`xruser` reported that `xrpioneer2` charged from approximately 45% to 75% and
returned immediately to approximately 45% when the vehicle was switched on. The
normal bounded History proves the transition but does not retain pack voltage,
pack current or cell-extrema series.

## Accepted scope

- separate encrypted on-demand debug table;
- exact vehicle allowlist and absolute automatic deadline;
- numeric/boolean `display/*`, `charging/*` and `bms/*` values only;
- `display/soc` is explicitly Display-CAN SOC and remains canonical;
  REV15 additionally publishes the provisional Pioneer `bms/soc_internal` and
  the display-correlated `bms/soc_display`, which are stored as independent
  diagnostic signals and never substituted for `display/soc`;
- GPS and arbitrary structured payloads excluded;
- seven-day TTL and a dedicated daily-write alarm;
- chronological per-vehicle key and reproducible CSV export;
- first controlled activation for `xrpioneer2`.

## Acceptance evidence

- inline Lambda code compiles;
- 24 focused foundation tests pass and prove vehicle, expiry, namespace and
  scalar-type gates;
- Change Set `dbg-001-xrpioneer2-20260901` contained only the intended additive table/alarm,
  scoped IAM/configuration changes and in-place Lambda update;
- stack `mot-aws-3-1` reached `UPDATE_COMPLETE`; on-demand billing, encryption,
  seven-day TTL, 250,000-write alarm and the exact debug parameters read back;
- capture is active only for `xrpioneer2`; parameter-only Change Set
  `dbg-001-extend-xrpioneer2-20260910` extended the deadline to epoch
  `1789077599` (2026-09-10 23:59:59 CEST) without resource replacement;
- the first consistent query returned 221 rows, including pack voltage/current,
  pack/vehicle power, cell minimum/maximum/delta, SOC and charging states;
- `pioneer` returned zero debug rows and no `debug_ingest_failed` event appeared;
- the dependency-free CSV exporter produced a 408-row bounded smoke export;
- capture stops automatically after its configured deadline.

After the successful XIAO REV15 WebFlash on 2026-09-03, live State and debug
read-back confirmed all three SOC signals for `xrpioneer2`. Across 212 matched
five-second samples, `bms/soc_display` followed canonical `display/soc` exactly.
The provisional `bms/soc_internal` remained four to five whole percentage points
lower, alternating at the individual integer update boundaries. Example live
values were Display-CAN 63%, Standard-CAN display copy 63% and internal candidate
59%. The signals therefore arrive and persist through the intended debug path.

On 2026-09-03 the capture recorded a second relevant end-of-charge event. The
adapter reported roughly 2.35 kW and 43.8 A through 10:51:18 CEST. At 10:52:52,
after a 94-second telemetry gap, charging and plugged state both changed to false,
pack current/power read zero, the Standard-CAN status byte changed from `0x20` to
`0x48`, and Display-CAN SOC changed from the last observed 97% to 100%. There was
no preceding current taper. The adapter later reconnected with `brownout`; its
heartbeat uptime places the restart at approximately 10:56:40. Driving began at
about 10:59 and SOC then decreased normally. These data support an abrupt
vehicle/connection-state transition more strongly than a normal charge-station
taper, but cannot independently prove which physical controller initiated it.

## Closure and future diagnostics

Microlino has been asked whether additional Standard-CAN BMS PIDs can be shared.
New confirmed numeric/boolean `bms/*` topics fit the capture contract without a
data-model change, but decoder implementation and signal semantics still require
separate validation.

DBG-001 closes the MOT-scoped implementation and acceptance of the fail-closed
capture path, export tooling and REV15 SOC diagnostic evidence. The generic
debug capability remains available for future explicitly bounded investigations;
using it operationally does not reopen this sprint. Any new decoder or product
behaviour discovered through a later capture requires its own work package.
