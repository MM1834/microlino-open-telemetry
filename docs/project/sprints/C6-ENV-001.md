# C6-ENV-001 — Unified C6 Build Environments

**Status:** Active — repository preparation; unprovisioned hardware gate open

**Started:** 2026-08-11

## Objective

Maintain exactly one firmware environment per ESP32-C6 board. Both canonical
images include AWS IoT, ABRP, Dual-CAN, GPS, local administration and OTA. AWS is
a runtime capability: a device without a valid `/aws` credential set remains a
fully functional local adapter and performs no AWS connection attempts.

## Canonical environments

| Board | Environment | Flash |
|---|---|---:|
| Muse Lab nanoESP32-C6-N16 | `nanoesp32c6-n16` | 16 MB |
| Seeed XIAO ESP32-C6 | `xiao-esp32c6` | 4 MB |

The former `nanoesp32c6-n16-aws` and `xiao-esp32c6-aws` names are removed. This
does not change deployed devices or erase their LittleFS credentials; it only
removes duplicate build definitions for future artifacts.

## Safety and acceptance gates

- both canonical environments compile with `MOT_AWS_IOT=1` and LittleFS;
- missing credential files cause a bounded disabled AWS state with no reconnect
  work, while local WebUI, CAN, GPS, OTA and ABRP remain cooperative;
- the XIAO `firmware.bin` remains at or below 85% of one OTA app slot;
- provisioning tooling accepts only the two canonical C6 names;
- all repository tests and C6 builds pass;
- before rollout to another device, one unprovisioned C6 must physically pass
  boot, protected setup, local WebUI, ABRP-disabled operation and OTA without an
  `/aws` credential set.

## Current boundary

Repository preparation may be merged without touching the three deployed C6
devices. Hardware rollout remains blocked until a spare C6 is available or the
next board delivery arrives. The existing N16 and two XIAO devices remain on their
already validated images.

Repository preparation is complete. The work package remains active only for the

## First unprovisioned N16 check — 2026-08-14

One newly delivered, unsoldered nanoESP32-C6-N16 was identified over its CH343
USB-UART as an ESP32-C6 revision 0.2 with physically detected 16 MB flash. The
test erased only this new board and wrote the canonical N16 bootloader, 16 MB
partition table, application and a valid empty LittleFS image. Every written
region passed esptool hash verification.

The clean board then ran continuously as `MOT-A0AED9` with:

- protected fallback/setup AP active and no WiFi profile configured;
- `AWS=disconnected credentials=no publishes=0`, with no AWS reconnect activity;
- both internal TWAI controllers alive at zero frames and zero errors;
- expected `GPS_NOT_DETECTED` because no receiver was attached;
- no crash or reboot loop during the observation window.

This is sufficient to release that individual module for soldering. Electrical
CAN-transceiver and GPS validation necessarily follows assembly. The work package
remains active until the authenticated setup/WebUI and browser-OTA path are also
performed once on this credential-free image.
