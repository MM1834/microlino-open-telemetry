# v1.0.0-rc.1 — Repository and Documentation Consolidation

> **Status:** Complete; published as `v1.0.0-rc.1`
>
> **Audience:** Maintainer, release reviewer and contributor
>
> **Started:** 2026-08-04
>
> **Completed:** 2026-08-04
>
> **Predecessor:** REL-001 portal pilot release

## Objective

Turn the accepted REL-001 pilot repository into one understandable release
candidate. The working tree must expose current product, operating and validation
knowledge while Git history remains the source for superseded sprint packages,
patch manifests and intermediate release narration.

This sprint changes repository knowledge organization. It does not by itself
authorize firmware flashing, AWS mutation, credential changes or portal upload.

## Included scope

- consolidate REL-001 scope, evidence and known limitations into one RC record;
- remove completed SPR-0003 and SPR-0004 delivery records from the current tree;
- remove the in-tree historical archive after preserving its history in Git;
- remove obsolete package copies, backup trees and historical README files;
- keep only active work packages and current validation evidence visible;
- repair navigation, governance, release-process and documentation-audit links;
- report exact before/after file counts and link-validation results.

## Release baseline inherited from REL-001

- Cognito login/logout and per-user vehicle isolation;
- controlled administrator claim issuance and single-use vehicle claims;
- hosted portal at `/dashboard/` with `/motbeta/` retained as fallback;
- WROOM local-security and AWS functional evidence;
- LilyGO WiFi-to-LTE AWS IoT functional and road-test evidence;
- bounded telemetry-history pilot for the controlled identities.

## Explicitly deferred

- public self-registration;
- ownership transfer, device replacement and automated recovery;
- automated certificate provisioning or rotation;
- cloud-managed OTA;
- production-scale fleet administration;
- extended adverse-condition and soak qualification;
- final `v1.0.0` release tag and general-public release approval.

## Consolidation rules

1. Current behaviour belongs in architecture, firmware, API or operator pages.
2. Current state belongs in governance documents.
3. Current acceptance evidence belongs under `docs/testing/`.
4. Release scope belongs in one versioned release note.
5. Completed delivery narration is recovered from Git history when needed and is
   not duplicated in the working tree.
6. Active work packages remain until their open gates are completed or deferred.

## Acceptance gates

- [x] One `v1.0.0-rc.1` release note owns the candidate scope.
- [x] REL-001 is represented as predecessor evidence, not a parallel active release.
- [x] Completed SPR-0003/SPR-0004 files are absent from the current tree.
- [x] `docs/archive/` and redundant package copies are absent from the current tree.
- [x] Current documentation has no links to removed archive or sprint files.
- [x] Governance and release workflow identify `v1.0.0-rc.1` as the active candidate.
- [x] Documentation audit and internal-link validation pass.
- [x] The final diff contains no credentials, generated dependencies or firmware
      behaviour changes.

## Stop conditions

- Do not remove current operational instructions unless their information has a
  surviving canonical owner.
- Do not convert an unvalidated claim into current release evidence.
- Do not rename firmware-visible legacy versions as part of documentation cleanup.
- Do not tag or promote `v1.0.0` until the remaining release gates are explicitly
  accepted.
