# C6-SVC-001 — C6 Local-Service Parity

**Status:** Active — architecture and flash baseline

**Started:** 2026-08-11

## Objective

Restore ABRP and the authenticated local onboarding wizard on the shared ESP32-C6
firmware without creating C6-only service implementations. ABRP must coexist with
AWS IoT in the same image and remain independently selectable at runtime.

## Scope

- decouple the existing ABRP client from WROOM-specific configuration and GPS;
- use one shared ABRP runtime contract from WROOM and C6, and converge LilyGO when
  doing so does not regress its WiFi-only ABRP boundary;
- persist ABRP enabled state, API key and user token in C6 configuration;
- add authenticated C6 ABRP configuration, diagnostics and manual test route;
- lift reusable onboarding flow/presentation into common components and expose the
  local seven-step wizard on C6;
- preserve Dual-CAN, GPS, dual-profile WiFi, AWS, OTA, backup/restore and recovery;
- keep AWS and ABRP as independent runtime services in one production image.

## Build policy

- `nanoesp32c6-n16-aws` is the primary production/pilot image.
- `xiao-esp32c6-aws` must compile from the same source without feature forks.
- Base/non-AWS environments remain temporary CI and size-comparison gates during
  this sprint; they are not separate product firmware generations.
- Removal of the base environments requires a later explicit cleanup after the
  AWS-capable image is proven to run correctly without provisioned AWS credentials.

## XIAO 4 MB safety gates

1. Preserve dual OTA app slots and the current LittleFS partition.
2. Fail the sprint gate if the XIAO-AWS application exceeds 85% of its app slot.
3. Record before/after binary and partition usage.
4. Build and test N16 before flashing XIAO.
5. Do not flash XIAO until ABRP-disabled runtime and OTA compatibility pass on N16.
6. Keep ABRP default-off and never expose its credentials in HTML, diagnostics or
   non-secret backup exports.

## Acceptance

- all four C6 PlatformIO environments build;
- focused configuration, WebUI/authentication, ABRP and onboarding tests pass;
- ABRP-disabled operation has no periodic network work;
- ABRP test/send works over WiFi while AWS remains connected in the AWS image;
- local wizard can be resumed, completed and restarted under `admin` auth;
- backup/restore preserves service state without exporting secrets;
- XIAO-AWS stays at or below 85% app-slot usage;
- N16 hardware acceptance passes before any optional XIAO hardware run.

The XIAO-AWS gate permits at most 1,448,345 used app bytes (85%). Its measured

415,648 bytes. This sprint must optimize or narrow presentation code before a
XIAO flash if the shared ABRP and wizard additions exceed the 85% gate.

## Repository implementation evidence

- The former WROOM-coupled ABRP source now accepts board-neutral settings and a
  GPS callback. WROOM and C6 use adapters over the same implementation.
- HTTPS sending runs in a separate FreeRTOS task; the main C6 loop continues to
  service Dual-CAN, GPS, WiFi, WebUI and AWS.
- C6 persists ABRP enabled state and credentials, redacts credentials from normal
  exports/HTML/diagnostics and exposes authenticated same-origin status/test paths.
- C6 uses the shared seven-step onboarding model and shared navigation/progress
  helpers. Existing configured installations migrate as completed; clean devices
  enter the wizard.
- N16 base/AWS, XIAO base/AWS and WROOM base/AWS builds pass.
- 34 focused C6/WROOM service, security and dual-WiFi tests pass.

No XIAO image has been flashed during this implementation stage.

## Explicit non-goals

- ABRP through LilyGO LTE;
- cloud/account onboarding in the local firmware wizard;
- remote fleet OTA, signed rollback or Secure Boot;
- removing C6 base environments before the unified AWS-capable runtime is proven.
