# Validation

## Both boards

1. Confirm the WebUI header shows the sprint-based firmware version and correct AWS/MQTT variant.
2. Open `/api/status` and confirm firmware, CAN, GPS and service state are present.
3. Run the System Health check.
4. Confirm UTC is either a valid ISO-8601 timestamp or `not-synchronized`.
5. Confirm GPS reports its current state without requiring a valid fix.
6. Confirm CAN 1 remains configurable and CAN 2 is shown only as unavailable/reserved.
7. Confirm service selections persist after reboot.
8. Test configuration export/import and Factory Reset.

## ESP32-WROOM

System Health must include:

- WiFi, DNS, TCP and MQTT diagnostics
- CAN health
- GPS module started/seen/fix state
- latitude, longitude, satellites, HDOP and fix age
- UTC and uptime

## LilyGO T-A7670

System Health must include:

- network state
- LTE modem state
- GPS state
- CAN state
- MQTT state
- ABRP state
- UTC, uptime, board, sprint and build variant

Existing LilyGO specialist tests remain available:

- LTE debug
- LTE RX debug
- LTE TCP test
- MQTT debug
- LTE MQTT trace
- CAN latest frames
- ABRP test send

## Release gate

Both MQTT builds and both AWS builds compile, boot, expose the correct version, and pass the applicable checks above before commit.
