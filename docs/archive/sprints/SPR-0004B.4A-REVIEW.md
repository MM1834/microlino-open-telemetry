# SPR-0004B.4A Review

## Architekturentscheid
Phase 4A trennt Verbindungsinfrastruktur und fachliche Telemetrie. Der WebSocket wird bereits authentifiziert, hält eine Subscription pro Fahrzeug und bestätigt Heartbeats. Die eigentlichen SOC-, Lade- und Batteriedaten bleiben bis Phase 4B auf dem bestehenden REST-Pfad.

## Gründe
- Die Verbindung kann unabhängig von noch nicht dekodierten Batteriesignalen getestet werden.
- Fehler lassen sich klar zwischen Authentifizierung, WebSocket, Subscription und Telemetrie-Fan-out eingrenzen.
- Das produktive Dashboard behält während der Einführung sein bewährtes 5-Sekunden-Polling.
- Die Reconnect-Zeiten entsprechen dem Fahrzeug-Sendeintervall und vermeiden unnötig aggressive Wiederverbindungen.

## Bekannte Einschränkung
Browser-WebSockets erlauben keinen frei gesetzten Authorization-Header. Das Access Token wird deshalb beim Verbindungsaufbau als Query-Parameter übertragen. Es wird ausschliesslich über TLS genutzt und nicht im Dashboard gespeichert, ausser im bereits bestehenden Session-Token-Store. API-Gateway-Access-Logs sollten Query-Strings nicht unnötig protokollieren.
