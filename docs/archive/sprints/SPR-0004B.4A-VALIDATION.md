# SPR-0004B.4A Validation

## Automatische lokale Prüfungen

```bash
node --check dashboard/js/live/websocket-client.js
node --check dashboard/js/providers/aws-backend-provider.js
node --check dashboard/js/app.js
unzip -t SPR-0004B.4A-LIVE-INFRASTRUCTURE.zip
```

## AWS-Prüfung

1. CloudFormation-Stack ist `UPDATE_COMPLETE`.
2. Output `VehicleWebSocketUrl` ist vorhanden.
3. DynamoDB-Tabelle `mot-dev-live-connections` ist vorhanden.
4. Nach Dashboard-Login entsteht ein Eintrag mit `connectionId` und `userSub`.
5. Nach Fahrzeugauswahl enthält der Eintrag `vehicleId`.
6. `expiresAt` wird durch Heartbeat aktualisiert.
7. Beim Schliessen des Tabs wird der Eintrag über `$disconnect` entfernt; andernfalls räumt TTL später auf.

## Browser-Prüfung

1. Login durchführen.
2. DevTools Console öffnen.
3. Cloud zeigt `Online`.
4. Live zeigt zuerst `Verbinden…`, danach `Verbunden`.
5. Detail zeigt `Abonniert: <vehicleId>`.
6. Fahrzeug wechseln; Detail muss die neue Fahrzeug-ID zeigen.
7. Netzwerk kurz deaktivieren.
8. Erwartete Reconnect-Anzeige: 5 s, danach 15 s, 60 s, 120 s und maximal 300 s.
9. Netzwerk aktivieren; Live springt wieder auf `Verbunden`.
10. REST-Daten aktualisieren sich weiterhin alle 5 Sekunden.

## Abgrenzung
In Phase 4A werden keine Telemetriewerte über WebSocket übertragen. Das folgt in SPR-0004B.4B.
