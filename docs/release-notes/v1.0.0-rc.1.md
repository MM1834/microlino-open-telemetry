# v1.0.0-rc.1 Release Notes

> **Status:** Published release candidate
>
> **Date:** 2026-08-04
>
> **Predecessor:** REL-001 pilot release

## Purpose

`v1.0.0-rc.1` is the first consolidated repository release candidate. It carries
forward the accepted REL-001 portal pilot and presents the maintained system as one
product line instead of a sequence of implementation sprints.

## Included

- passive Microlino CAN telemetry on ESP32-WROOM and LilyGO T-A7670G paths;
- local authenticated setup, diagnostics, recovery and OTA controls;
- shared AWS IoT telemetry transport with per-device X.509 credentials;
- WiFi-preferred LilyGO operation with LTE/GPRS fallback;
- Cognito Authorization Code flow with PKCE;
- server-side per-user vehicle authorization for REST and WebSocket access;
- controlled single-use vehicle claiming;
- hosted portal at `/dashboard/`, with `/motbeta/` retained as rollback fallback;
- bounded SOC, charging, plugged and speed history for controlled pilot identities;
- consolidated current documentation and release evidence.

## Validated release evidence

REL-001 repository tests, hosted acceptance and device evidence are retained in
[the release-candidate validation record](../testing/REL-001-rc-validation.md).
The current governance status distinguishes repository evidence from deployed
state and from still-open qualification work.

## Known limitations and deferred work

- public self-registration is disabled;
- ownership transfer, device replacement and automated recovery are unavailable;
- certificate provisioning and rotation are manual;
- OTA is local rather than cloud-managed;
- retained hosting risk CLOUD-017 limits the portal to directly invited pilot users;
- extended LilyGO soak and adverse-condition qualification remain open;
- PlatformIO still exposes legacy environment names pending firmware-line
  simplification;
- firmware-visible legacy sprint version strings are not renamed by this
  documentation release candidate.

## Upgrade and deployment boundary

This release record does not authorize a deployment. Firmware upload, credential
mutation, AWS deployment and portal promotion require their current operational
procedures, exact target identification, validation and rollback evidence.

## Historical records

Intermediate README, SPR, manifest, patch and hotfix files were removed from the
working tree during consolidation. They remain recoverable from Git history and
the [checksummed pre-consolidation package](../history/HISTORY.md). Use the
canonical current documentation before consulting an older revision.
