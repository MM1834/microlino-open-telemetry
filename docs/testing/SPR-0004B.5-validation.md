# SPR-0004B.5 Validation

## Build

Build all normal firmware environments:

```bash
cd firmware/esp32-wroom
pio run -e esp32dev
pio run -e esp32dev-aws

cd ../lilygo-t-a7670
pio run -e lilygo-t-a7670
pio run -e T-A7670X-AWS
```

## ESP32-WROOM

1. Flash firmware and open the local configuration page.
2. Confirm `Microlino Display CAN` is selected after migration/default boot.
3. Confirm known frames still update SOC and speed.
4. Select `Microlino Standard CAN (template)`, save and reboot.
5. Confirm the selection persists.
6. Confirm CAN frames are received but no telemetry is decoded by the template.
7. Export configuration and confirm `can1Profile` is `2`.
8. Restore a configuration with `can1Profile: 0` and confirm Display CAN becomes active.

## LilyGO

1. Flash firmware and open `/config`.
2. Repeat the Display/Standard profile persistence checks.
3. Open `/api/lilygo/can` and confirm `profileId`, `profileKey`, `profileName` and `profileImplemented` match the selected profile.
4. Export and restore the configuration; confirm `canProfile` survives.

## Regression

- no MQTT topic changes
- no AWS resource changes
- no ABRP behaviour changes
- CAN remains receive-only
- Display-CAN values are unchanged
